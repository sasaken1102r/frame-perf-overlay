# frame-perf-overlay

Steam Frame 用の小さな性能パネルです。SteamVR の中に出しっぱなしにして、アプリの fps、GPU・CPU の負荷、温度、消費電力、電池の残量、Steam Link の無線の状態をひと目で見られるようにします。ゲームがカクつく理由や、本体が熱くなっている様子がその場で分かります。ヘッドセット本体（aarch64 の SteamOS）の上で、OpenVR のオーバーレイとして動きます。

[English](README.md)

https://github.com/user-attachments/assets/a749d90a-c6e8-4ea2-a881-61332d7e9ab4

Half-Life: Alyx を遊びながらヘッドセットの中で撮った動画です（音なし）。パネルは左下に出たままで、SteamVR ダッシュボードの **Perf** タブから位置・大きさ・言語を変えられます。

![性能パネル](docs/images/panel-ja.png)

パネルは頭に追従し、既定では視界の左下に出ます。左手・右手のコントローラーに腕時計のように付けることもでき、既定のレイアウトでは、いちばん下の行に時刻を出します。固定先・位置・向き・大きさ・透明度・時計・言語（日本語 / English）は SteamVR のダッシュボードから変えられます。言語の既定は Steam の言語設定に合わせます（日本語なら日本語、それ以外は英語）。

パネルは、ウィジェット（「フレーム」「電力」「温度」「CPU」「GPU・メモリ」「通信」「電池」「その他」「CPU 上位」「メモリ上位」）を並べたものです。ダッシュボードのタブの**レイアウト**のページで、ウィジェットを列の間で動かしたり、足したり外したりでき、カードの**小さく表示**をオフにすると、もっと多くの項目を出せます。**プロファイル**のページでは、レイアウトを保存して切り替えられます。パネルに出していないウィジェットの値は読みません。パネルが誰にも見えていないとき（隠している・ヘッドセットを外している）は、ダッシュボードのタブを開いていない限り、何も読みません。

![SteamVR ダッシュボードの設定タブの「レイアウト」のページ](docs/images/settings-ja.png)

これらの画像はヘッドセットの中で撮ったものではなく、アプリ自身が書き出したもの（`--dump-png` / `--dump-settings-png`）です。パネルの画像は既定のレイアウトで、数値はダミーの値です。設定の画像は、「温度」のカードを選んだ**レイアウト**のページです。

## 表示する項目

既定のレイアウトは、今までパネルに出していたものを 2 列に並べています（左に「フレーム」「電力」「温度」「CPU」、右に「GPU・メモリ」「通信」「電池」「その他」）。「温度」と「電池」は小さく表示なので、前のように横長で低いパネルになります。カードの小さく表示をオフにすると、もっと多くの項目が出ます（例: 「温度」なら、DDR とそのほかのすべての温度）。ウィジェットはそれぞれ 1 枚のカードで、グラフのあるものは直近 30 秒を出します。

| ウィジェット | 大きい数字 | 補足 | グラフ |
|---|---|---|---|
| フレーム | アプリの fps と表示のリフレッシュレート（例: `72 fps / 90Hz`） | GPU・CPU の 1 フレームあたりの時間（ms）、再投影の割合、落ちたフレーム数 | fps の線、点線がリフレッシュレート。SteamVR がアプリをリフレッシュレートの半分（や 1/3）に抑えているときは黄色いバッジ |
| 電力 | 主電源レールの消費電力（vph、W） | その下で測っているレールの合計（「各ch計」） | 主電源レールの電力、しきい値の点線 |
| 温度 | CPU 温度（いちばん熱いコア） | GPU、DDR、ファン回転数。電池、画面付近・排気・放熱（ヒートシンク付近）の温度 | CPU と GPU、しきい値の点線。熱で CPU か GPU のクロックが制限されている間は、赤いバッジとカードの赤い枠 |
| CPU | 使用率（全体と、かっこの中に最も忙しいコア） | 最速クラスタのクロック（同じ行） | |
| GPU・メモリ | GPU 負荷（VR のアプリと SteamVR の分、%） | GPU クロック（と最大）、メモリの使用量 / 全体 | GPU 負荷 |
| 通信 | 無線。Steam Link のドングルに PC がつながっていれば「直通」、いなければ本体がつないでいる Wi-Fi（家の Wi-Fi など）の親機を「Wi-Fi」として出します | 電波の強さ（Wi-Fi アイコンと dBm）、実際に流れている量（↓ Frame へ、↑ Frame から）、リンク速度。どちらにもつながっていないときはグレーのアイコンに斜線 | |
| 電池 | 本体の電池（%）と状態（充電中は稲妻） | 電池に出入りする電力（W）。小さく表示にしていないカードでは、電圧 × 電流の行も | |
| その他 | 左手・右手のコントローラーの電池（充電中は稲妻） | 本体の時計の時刻（既定は 24 時間制。設定で 12 時間制や非表示にできます） | |

「GPU・メモリ」とプロセスの一覧以外のウィジェットには、**小さく表示**のスイッチがあります。小さく表示がオンのカードが上の表のものです。パレットから足したウィジェットは小さく表示で始まり、スイッチができる前のレイアウトの「フレーム」「CPU」「電力」「通信」「その他」も小さく表示になるので、見た目は前のままです。「電池」と「温度」は今までの意味のままで、小さく表示は短いカード（電池: % と W の行、温度: CPU / GPU / ファンとグラフ）、オフにすると下のすべてが出ます。小さく表示をオフにすると、カードが大きくなって次が加わります:

| ウィジェット | 小さく表示をオフにすると加わるもの |
|---|---|
| フレーム | fps の下に 2 本のグラフ: 1 フレームあたりの CPU 時間と GPU 時間（それぞれ、読み取りごとのいちばん遅いフレーム）。平均と最悪の値（ms）と、フレームの目標時間を点線で |
| CPU | コアごとのバー。そのあとクラスタごとのクロックと今の最大（Playtime や熱の制限で下がっている間は、黄色で「**本来**」のあとにハードウェアの最大） |
| 電力 | vph の電圧。その下に各レール（CPU の apc0-2、GPU、NPU、s1c / s3c / s6c、bob）の W・V と、vph に対する割合のバー。どのレールでも測っていない分（**未計測**） |
| 電池 | 電圧 × 電流の行、容量（mAh: 今 / 満充電 / 設計）、充電中・放電中は満充電まで・空になるまでの時間、電池の状態とサイクル数、充電モード（CC、CV、Full、Paused など）、設定電流。ケーブルがつながっているときは、USB の種類、USB-PD で充電器が出せるもの、実際の入力、途中で落ちた電圧（**電圧の落ち**。出せる電圧の 10 % から黄色） |
| 温度 | DDR と、11 か所: 電池、画面付近・排気・放熱の近く、NPU、カメラ、映像、Wi-Fi チップの近く、ストレージ、nRF の無線、40 ピンの端子 |
| 通信 | 使っている方 1 つではなく、両方の回線を 1 枚のカードに: **直通**（Steam Link のドングル、`wlanap`）と **Wi-Fi**（`wlan0`）。それぞれ電波の強さ、↓/↑ の量、リンク速度、帯域、チャンネル、チャンネル幅、その回線での本体の IP アドレス。つながっていなければ**未接続** |
| その他 | 起動から（本体の電源を入れてからの時間。スリープも含む）、前面のアプリ（**アプリ**）、このオーバーレイの負荷（**パネル負荷**: 1 コアに対する CPU %、メモリ、電力の目安） |

プロセスを一覧にするウィジェットが、あと 2 つあります:

| ウィジェット | 出すもの |
|---|---|
| CPU 上位 | いちばん忙しいプロセス。1 コアに対する %（4 コアがフルで動けば 400 %）で、2 秒おき |
| メモリ上位 | メモリをいちばん使っているプロセス（実メモリ、MiB） |

この 2 つの設定: 行数（1〜50、既定は 15）、**同じ名前は 1 行に**（同じ名前のプロセスを足し合わせ、名前のあとに `×N` を付ける）、**システムを隠す**（`hide_rules.json` に書いてある SteamOS・Steam・SteamVR のプロセスを省く。[設定ファイル](#設定ファイル)を参照）。

しきい値を超えた数字は黄色、さらに超えると赤になります。しきい値は設定ファイルで変えられます。

![警告の色（ダミーの値）](docs/images/panel-warnings-ja.png)

## 必要なもの

- 開発者モードを有効にして SSH で入れる Steam Frame（設定 → システム → 開発者モードを有効化、開発者の項目でパスワードを設定）。SSH を有効にすると、同じネットワークにいてパスワードを知っている人は誰でもヘッドセットに入れるので、推測されにくいパスワードにしてください
- ヘッドセットにファイルをコピーする手段（PC からの `scp` など）
- sudo は要りません。すべてホームフォルダに入ります

## インストール

### いちばんかんたん：Frame の中だけで入れる（おすすめ）

PC は要りません。Frame の Konsole（画面下のバーの ＋ →「プログラムを起動」→ Konsole）で次のコマンドを入力して Enter を押し、メニューで **4**（frame-perf-overlay）を選びます。

```sh
curl -fsSL https://frame.sasaken1102s.net | sh
```

- 最初の 1 回だけ、Steam 設定 → システム →「開発者モードを有効化」をオンにしておきます（オフだと ＋ の一覧に Konsole が出ません）
- ほかのアプリ（frameeyeosc・frame-jp-keyboard・frame-mic-tuner）も同じメニューから一緒に入れられます
- 更新は、同じコマンドで同じ番号を選ぶだけ。アンインストールはメニューの `u` から
- くわしい手順と動画：https://frame.sasaken1102s.net
- 質問なしで入れるなら `curl -fsSL https://frame.sasaken1102s.net | sh -s -- install perf`

入るもの・オプションは、下の「PC から入れる」と同じです（中で `install.sh` を実行しています）。

### PC から入れる

[リリースページ](https://github.com/sasaken1102r/frame-perf-overlay/releases)から `frame-perf-overlay-<バージョン>.tar.gz` をダウンロードして、ヘッドセットにコピーします。PC からなら例えば:

```sh
scp frame-perf-overlay-*.tar.gz steamos@<ヘッドセットのIP>:
```

そのあとヘッドセット上で（`ssh steamos@<ヘッドセットのIP>`）:

```sh
tar xzf frame-perf-overlay-*.tar.gz
cd frame-perf-overlay
./install.sh
```

入るもの:

- 実行ファイル: `~/.local/bin/frame-perf-overlay`
- ＋の一覧に出すための `.desktop` とアイコン: `~/.local/share/applications/frame-perf-overlay.desktop`、`~/.local/share/icons/hicolor/{48x48,128x128,256x256}/apps/frame-perf-overlay.png`
- SteamVR と一緒に起動する systemd のユーザーサービス: `~/.config/systemd/user/frame-perf-overlay.service`
- ［更新する］ボタンが使う更新スクリプト: `~/.local/share/frame-perf-overlay/frame-update.sh`、次の更新で使うインストールのオプション: `~/.config/frame-perf-overlay/install-args`（[更新](#更新)を参照）

SteamVR が動いていれば、その場でパネルが出ます。SteamOS を更新しても消えません。新しい版は Perf タブの帯から入れられます（[更新](#更新)）。手で更新するときは、新しいバージョンのフォルダで `./install.sh` を実行します。

オプション:

- `./install.sh --no-autostart`: サービスを有効にせずに入れます。ダッシュボードの＋から自分で起動して使います（下の「使い方」）
- `./install.sh --uninstall`: 止めて、上のファイルを消します。`~/.config/frame-perf-overlay/` のフォルダ（設定と `install-args`）は残すので、要らなければそのフォルダも消してください。更新の仕組みのキャッシュとログ（`~/.cache/frame-perf-overlay/`）があれば、それも消して構いません

## 使い方

- **パネル**: 自動起動がオンなら、SteamVR が動いている間はずっと出ています。操作は要りません
- **言語は Steam の言語設定に合わせます**（Steam が日本語なら日本語、それ以外は英語）。変えるときは **Perf** タブ（下）の左下の「言語」で切り替えます
- **設定**: SteamVR のダッシュボードを開き、下の並びの **Perf** のタブを選びます。レーザーポインターで押して操作します

  | ボタン | 動き |
  |---|---|
  | 配置 / レイアウト / プロファイル | タブの 3 つのページ（見出しの隣）。タブは「配置」のページで開き、下のボタンはそこにあります |
  | 表示: オン / オフ | パネルを出す・隠す。隠している間は値の読み取りと描画も止まります |
  | 大きさ − / ＋ | パネルの 1 列の幅を 2cm ずつ（6cm〜1m）。列の多いレイアウトは、列の数だけ倍の幅になります |
  | 透明度 − / ＋ | 10% ずつ（20%〜100%） |
  | 時計: オフ / 12h / 24h | パネルのいちばん下の行の時計。本体の時刻を、24 時間制（既定）か 12 時間制（AM / PM）で出すか、出さないか |
  | 既定に戻す | 表示・固定先・位置と向き（頭と両手）・傾けると消す・時計・大きさ・透明度を既定に戻します。言語・しきい値・フォント・新しい版の確認の設定はそのまま |
  | 固定先: 頭 / 左手 / 右手 | パネルをどこに付けるか。頭（目の前に出て頭に追従）か、左手・右手のコントローラー（腕時計のように）。下の位置と向きのボタンは、いつも選んでいる固定先のものを動かします。左右の手は、それぞれの位置と向きを覚えています |
  | 左上 / 右上 / 左下 / 中央下 / 右下（頭） | 視界のその位置へ動かして、パネルを自分の方に向けます |
  | 手首の標準の位置（手） | その手のパネルを標準の場所と向きに戻します（設定ファイルでは `x` 0・`y` 0.05・`z` 0.08・`pitch` −90） |
  | ← 左 / 右 → / ↑ 上 / ↓ 下 | 頭: 2cm ずつ動かします。手: パネル自身の向き（今回している向き）で、パネルの右・左・上・下の辺の方へ 1cm ずつ（±50cm まで）。どちらも向きは変えません |
  | 近く / 遠く | 頭: 見える方向はそのままで 5cm ずつ近づけ・遠ざけます（20cm〜3m）。手: パネルの面の表の方（見ている人の方）か、その逆へ 1cm ずつ（±50cm まで） |
  | 向き: ← 左向き / 右向き → / ↑ 上向き / ↓ 下向き | パネルの面の向きを、選んだ刻みで変えます。頭でも手でも同じで、「↑ 上向き」で面がパネルの上側へ、「右向き →」で右側へ向きます（左右は ±180°、上下は頭なら正面向きから、手なら寝かせた向きから ±90° まで）。刻みの目盛りにそろえるので、16.7° から「5° ずつ」なら 20° か 15° になります |
  | ⟲ 左に回す / 右に回す ⟳ | パネルを画面の中で回します（roll）。面を見て反時計回り / 時計回りに、選んだ刻みで（±180° まで）。パネルが水平に見えないときに使います |
  | 1° ずつ / 5° ずつ | 向きのボタンと回すボタンを 1 回押したときに動く量。アプリを起動するたびに 1° に戻ります（保存しません） |
  | 自分に向ける（頭） | 位置はそのままで、パネルの面を頭の方へ向けます。「左に回す / 右に回す」で合わせた回転（roll）はそのまま残します |
  | 正面向き（頭） | 回転をなくして、顔の正面と平行に戻します（この機能を入れる前の見た目） |
  | 傾けると消す: オン / オフ（手） | オンなら、パネルの面が頭（ヘッドセット）の方から外れるほど薄くして消します（腕時計のように、見たときだけ出ます）。オフならどの角度でも出したまま |
  | 消える角度 − / ＋（手） | 5° ずつ。パネルの面と頭（ヘッドセット）の方向との角度が何度で消えきるか（35°〜90°）。その 30° 手前から薄くなり始めます。既定は 45〜75° |
  | 言語 | 日本語 / English。すぐ切り替わります |
  | 自動起動: オン / オフ | systemd のサービスを有効・無効にします。効くのは次の SteamVR 起動から |
  | アプリを終了 | 3 秒以内にもう一度押すと終了します |

  変更はすぐ反映され、設定ファイルに保存されます。
- **レイアウトのページ**: 左のカードにパネルの列が出ていて、ウィジェットごとに 1 枚のカードになっています。カードをドラッグすると、別の場所や列へ動かせます（点線の「新しい列」に落とすと列が増えます。8 列、1 列に 16 個まで）。右のパレット（「ウィジェット」）に落とすと外します。パレットのウィジェットをタップすると、いちばん短い列に足します。好きな場所へドラッグしても足せます。カードをタップして選ぶと、パレットの下にその設定が出ます（「GPU・メモリ」とプロセスの一覧以外のウィジェットは［小さく表示］、「CPU 上位」「メモリ上位」は行数・［同じ名前は 1 行に］・［システムを隠す］、それと［外す］）。変更はすぐ保存され、パネルにも出ます。列が収まらないときは、スティックで列をスクロールできます
- **プロファイルのページ**: プロファイルは保存したレイアウトです（列・ウィジェットとその設定。位置やアプリの設定は入りません）。［新しく作る］で今のレイアウトを保存し（8 個まで）、［使う］で選んだものを読み込み、［上書き保存］で今のレイアウトを「使用中」のプロファイルに書き込みます。［名前を変える］は SteamVR のキーボードを開き、［削除］は選んだものを消し、［既定に戻す］は既定のレイアウトに戻します（プロファイルは残ります）。［使う］と［既定に戻す］は、レイアウトの変更が消えるときはもう一度押すと動き、［削除］はいつももう一度押すと動きます。プロファイルは `~/.config/frame-perf-overlay/profiles/` のファイルです
- **手に付けたとき**: パネルはコントローラー（SteamVR のコントローラーのトラッキング。ハンドトラッキングではありません）に付いていきます。コントローラーか本体のトラッキングが外れるとすぐ隠れ、戻るとまた薄く出てきます。隠れている間も **Perf** タブは使えます。ちょうどよい位置と向きはコントローラーの持ち方で変わるので、ヘッドセットをかぶったまま合わせてください
- **更新**: 見出しの右（見出しの行の中）の帯に、今の版がいつも出ています（例: `最新版です（0.2.0）`。自動確認を止めているときは、確かめるまで版の数字だけ）。［今すぐ確かめる］を押すと、その場で GitHub に確かめに行きます（自動確認を止めていても使えます）。帯の見え方:
  - **新しい版があるとき**: ピンクの枠で「新しい版 0.2.1 があります」と［今すぐ確かめる］［更新する］。［更新する］を押すと「0.2.1 に更新しますか？」と［やめる］［更新する］が出て、もう一度［更新する］を押すとインストールが始まります
  - **更新中**: 「更新中: ダウンロード中」などの手順と、右に小さく灰色で、途中でこの画面が閉じて開き直すことがある旨。新しい版が起動するときに、実際に一度閉じて開き直します
  - **更新できなかったとき**: 赤い枠で、理由と［もう一度］［閉じる］。今の版のまま動き続けます
  - **確かめられなかったとき**（ネットにつながっていない・GitHub に届かないなど）: 枠はそのままで、文字だけ赤くなり、［今すぐ確かめる］が出ます
  - **ここからは入れられない版のとき**（リリースに `SHA256SUMS` か、このアプリの tar.gz が無い）: ピンクの枠で、GitHub から手で更新してね、という案内（[インストール](#インストール)の手順で入れます）
- **＋（プログラムを起動）**: ダッシュボードの＋の一覧に **Frame Perf Overlay** が出ます。動いていなければ起動し、すでに動いていれば、もう一度起動するたびにパネルの表示と非表示を切り替えます
- **終わらせる**: ダッシュボードの下の **Perf** のアイコンにレーザーを合わせて「閉じる」を押すか、設定の「アプリを終了」を使います。安全な終了処理を通って終わり、次に SteamVR が起動するまで（または＋や `systemctl --user start frame-perf-overlay` で起動するまで）は止まったままです

## 設定ファイル

`~/.config/frame-perf-overlay/config.json`（`$XDG_CONFIG_HOME` があればその下）。無ければ既定値で動きます。ダッシュボードで変えた内容はここに保存されるので、手で書くのはしきい値やフォントを変えたいときだけです。書かなかった項目は既定値のままです。動いている間に保存すると、次の更新で読み直します。JSON が壊れているときは前の設定のまま動き、理由をログに出します。範囲外の値は丸め、知らないキーはログで知らせます。

別の設定ファイルを使うときは、`--config パス` を付けて起動します。

設定ファイルの隣の `hide_rules.json` には、「CPU 上位」「メモリ上位」で**システムを隠す**ときに省くものを書きます。アプリは最初に、組み込みの一覧（SteamOS のサービス、Steam、SteamVR）をここに書き出し、ファイルが変わるたびに読み直します。あとの版で増えた組み込みの規則は、起動したときに 1 回だけファイルに足します（自分で消した規則は戻しません）。手で直したファイルが使えないときは、最後にうまくいった一覧のまま動き、カードのいちばん下に 1 行出して、理由をログに出します。`name` はプロセスの名前かプログラムのファイル名に、`cgroup` はプロセスの cgroup のパス（`/proc/<pid>/cgroup`）に合わせます。どちらも `*` と `?` が使え、両方書いた規則は両方に合うものだけが対象です。`note` は自由なメモです。

```json
{
  "version": 1,
  "hide": [
    {"cgroup": "/system.slice/*", "note": "system services"},
    {"name": "vrserver", "note": "SteamVR server"}
  ]
}
```

## 自動起動

`./install.sh` は systemd のユーザーサービスを入れて有効にします。サービスは SteamVR（`steamvr.service`）が起動すると一緒に起動し、止まると一緒に止まります。それ以外の理由で終わったときは 5 秒後に起動し直します。「アプリを終了」やダッシュボードの「閉じる」で終わったときは、次の SteamVR 起動まで起動し直しません。

```sh
systemctl --user status frame-perf-overlay         # 動いているか
systemctl --user restart frame-perf-overlay        # 起動し直す
systemctl --user disable --now frame-perf-overlay  # 自動起動をやめて、今すぐ止める
systemctl --user enable frame-perf-overlay         # 自動起動を戻す
```

ダッシュボードの「自動起動」のボタンは、同じ `enable` / `disable` を実行します（`--now` は付けないので、動いているパネルは止まりません）。サービスのファイルが入っていないとき（自分でビルドして `install.sh` を使っていないときなど）は、ボタンがグレーになってその旨が出ます。

## 更新

`install.sh` が小さな更新スクリプトを `~/.local/share/frame-perf-overlay/frame-update.sh` に置き、パネルはこれを裏で動かします。

- **確かめるタイミング**: 起動したときと、そのあとは 1 時間おきにスクリプトに聞きますが、GitHub に問い合わせるのは 24 時間に 1 回までで、その間は前回の答えを使い回します（確かめられなかったときは 1 時間後にもう一度）。［今すぐ確かめる］はこの使い回しを飛ばします。[設定ファイル](#設定ファイル)の `update_check` を `false` にすると自動確認（起動時の分も）だけが止まり、［今すぐ確かめる］［更新する］はそのまま使えます
- **入れるもの**: ［更新する］で確かめたあとにだけ、リリースの tar.gz と `SHA256SUMS` を HTTPS でダウンロードし（github.com・api.github.com・`*.githubusercontent.com` だけ）、展開する前に tar.gz の SHA-256 を `SHA256SUMS` と照らし合わせます。`SHA256SUMS` が無い・合わないリリースは入れません。そのあと、そのリリースに入っている `install.sh` を、前回と同じオプション（`~/.config/frame-perf-overlay/install-args` に残してあります）で実行します。入るものは、手で `./install.sh` したときと同じです
- **動く場所**: インストールは systemd のユーザーの一時的なユニット `frame-perf-overlay-update` で行うので、`install.sh` がパネルを再起動しても続きます。ログは `~/.cache/frame-perf-overlay/update.log`（と `journalctl --user -u frame-perf-overlay-update`）
- **失敗したとき**: 今入っている版がそのまま残って動き続け、帯に理由が出ます
- **確かめられる範囲**: `SHA256SUMS` は同じ GitHub のリリースに置いたファイルなので、壊れたり途中で切れたりしたダウンロードは見つけられますが、リリースそのものが差し替えられた場合は防げません（署名ではなく、チェックサムです）
- **v0.1.0 から上げるとき**: v0.1.0 には更新の仕組みが入っていないので、0.2.0 へは一度だけ手で上げてください（ダウンロードして、そのフォルダで `./install.sh`。[インストール](#インストール)と同じ手順）。それ以降はパネルから更新できます

## うまく動かないとき

- **ログ**: `journalctl --user -u frame-perf-overlay -f`。`[VR] SteamVR につながりました` と出ていれば SteamVR につながっています
- **更新が失敗する・止まったままになる**: `~/.cache/frame-perf-overlay/update.log`（帯のエラーにも出ます）と `journalctl --user -u frame-perf-overlay-update` を確かめてください。失敗・中断しても今の版はそのままです
- **パネルが出ない**: SteamVR が動いているか（アプリは SteamVR を待つだけで、自分では起動しません）、Perf のタブで「表示」がオンか、サービスが動いているか（`systemctl --user status frame-perf-overlay`）を確かめてください。動いているときに＋から起動するとパネルが隠れるので、もう一度起動すると出ます
- **＋の一覧に出ない**: `./install.sh` をもう一度実行して、`~/.local/share/applications/frame-perf-overlay.desktop` があるか確かめてください
- **値が `--` や「センサーなし」「読み取り失敗」になる**: そのセンサーが見つからないか、読めていません。センサーは起動時に名前で探すので、SteamOS の更新で名前が変わるとこうなります。`frame-perf-overlay --print` で見つかったものを一覧できます
- **「フレーム」のカードが「SteamVR 未接続」**: まだ SteamVR につながっていません。3 秒おきに再試行します
- **文字化けする・字が出ない**: 設定ファイルの `font` / `font_bold` を確かめてください

## 値の正確さ

実機で別の方法と照らし合わせて確かめた値と、目安にとどまる値があります。後者はおおよその目安として見てください。

**別の方法と照らし合わせて確かめた値**

- **fps・再投影**: SteamVR 自身のフレームの記録と一致
- **CPU 使用率・クロック、GPU クロック、メモリ、本体の電池**: `top` や `/proc`・`/sys` の生の値と一致
- **CPU・GPU・電池の温度**: センサーの生の値と 1〜2℃ 以内で一致
- **ファンの回転数**: 生の値を 2 で割った値。SteamOS 自身のファン制御と同じ換算です
- **時計**: 本体の時計とタイムゾーンのままです。パネルの更新ごと（既定では 0.5 秒おき）に描き直します

**目安の値**

- **消費電力**: 各チャンネルが何の回路かは公開されていません。主電源レール（vph）が全体の供給にあたるというのは推測です。「各ch計」はその下で測っているチャンネルの合計で、すべての回路を数えているかは分かりません
- **GPU 負荷**: SteamVR が測っている 1 フレームあたりの GPU 時間に、アプリの fps を掛けた値です。数えるのは VR のアプリと SteamVR のコンポジタの分だけで（ほかのプログラムが使う GPU は入りません）、GPU の仕事が重なった分は 100% で止め、SteamVR がないときは `--` です。なので、本体全体の GPU 使用率ではありません。前に使っていた、カーネルがプロセスごとに出している GPU の値は使いません（SteamOS 0.5.6 では壊れているか、重いゲームの分をほとんど数えないため）
- **Steam Link で遊んでいるときの fps**: PC 側や回線で落ちたコマがいつも fps の低下として出るかは、まだ確かめていません
- **無線の流量**: 直通回線では、ストリーミング以外も含めた直通回線を流れる量すべてです。「Wi-Fi」のときは、本体が Wi-Fi で送受信している量すべて（ダウンロードやほかのアプリの分も含む）で、Steam Link の分だけではありません
- **電波の強さ**: 直通回線では PC からの応答（ACK）の電波の平均（本体側の値はそこでは 0 になるため）、「Wi-Fi」のときは本体が受けている親機の電波（OS が表示するのと同じ値）です。同じ距離でも数 dB ずれることがあります
- **画面・排気・放熱の温度**: 呼び名はセンサーの名前から付けたもので、正確な位置は公開されていません。ほかの場所（NPU、カメラ、映像、Wi-Fi、ストレージ、nRF、端子）も同じです
- **レールの電圧と未計測**（「電力」、小さく表示オフ）: 各レール自身の電圧の測定を、センサーが返すままに出しています。GPU のレールは 0.4 W 前後で数 mV しか読めないので「—」と出ます。未計測は vph からレールを引いた分なので、変換器の損失も含みます。チップごとに測るタイミングが少しずれるので、負荷が変わった直後は少しずれることがあります
- **満充電まで・空になるまで**（「電池」、小さく表示オフ）: 残量計の mAh を、平均した電流で割った値で、電流がそのまま続くと仮定しています。残量計自身の見積もりは、電流が 4 回変わってもほとんど動かなかったので使っていません
- **パネル負荷**（「その他」、小さく表示オフ）: CPU % とメモリはこのオーバーレイ自身の値です。W は目安で、忙しい CPU 時間全体に対するこのオーバーレイの割合に CPU のレールの電力を掛けたものなので、「≈」を付けて出します
- **CPU 上位**: 直近 2 秒の、プロセスごとの CPU 時間から出した、1 コアに対する % です。その間に始まった・終わったプロセスは、実際に使った分より少なく出ます
- **コントローラーの電池**: SteamVR が返す値をそのまま出しています

## 既知の問題

- 一部の値は目安です。[値の正確さ](#値の正確さ)を見てください
- CPU 温度はいちばん熱いコアの値なので、短い負荷で 1〜2℃ 跳ねます
- 電力のセンサー自体の更新が 1.5〜2 秒おきなので、電力は 2 秒おき、電池は 5 秒おきに読んでいます
- ダッシュボードのアイコンのボタンは「アプリを終了」ではなく「閉じる」と出ます（Steam のアプリではないため）
- コマンドラインの出力（`--print`、`--help`）とログは日本語だけです
- コントローラーのボタンの割り当てはありません。ダッシュボードか設定ファイルで変えてください
- 手に付けたパネルは、手そのものではなくコントローラーに付いていきます。「傾けると消す」がオンのとき、角度を確かめるのは、薄くなっている途中は 1 秒に 30 回、それ以外は 1 秒に 10 回です。トラッキングが外れてから隠れるまで、最大 0.1 秒ほどかかります

## プライバシー

- アプリ自体にテレメトリはありません。外部との通信は**新しい版の確認だけ**です: `api.github.com` に最新リリースを問い合わせ（`update_check` が on の間は、起動時と、そのあとは 24 時間に 1 回まで。確かめられなかったときは 1 時間後。［今すぐ確かめる］を押せばすぐにも）、実際にインストールを確認したときだけ、リリースの tar.gz と `SHA256SUMS` を `github.com` / `*.githubusercontent.com` から HTTPS でダウンロードします。それ以外は何も送りません（GitHub 側からは、ふつうの匿名の HTTP リクエストとして、ヘッドセットの IP と `curl` の user agent が見えるだけです）。パネルに出す Wi-Fi の状態は、ヘッドセット自身のカーネルに問い合わせるだけで、外には出ません
- Steam Link の直通回線と、本体がつないでいる Wi-Fi の親機については、ヘッドセット自身の Wi-Fi ドライバから、電波の強さ・リンク速度・チャンネル・送受信したバイト数と、それぞれの回線での本体自身の IP アドレス（「通信」の小さく表示をオフにしたとき）だけを本体の中で読んで表示しています。PC・親機・ヘッドセットの MAC アドレスや、Wi-Fi のネットワーク名（SSID）は、取り出さず、画面にもログにも出しません
- 「CPU 上位」「メモリ上位」は、ヘッドセットの `/proc` からプロセスごとの名前・CPU 時間・メモリを読み、「その他」は小さく表示をオフにすると、前面のアプリを SteamVR に問い合わせます。これらはパネルに出すだけで、保存・ログ・送信はしません
- 書き込むファイル: 設定ファイル（保存するときは、隣に一時ファイル `config.json.tmp` を書いてから置き換えます）、その隣の `hide_rules.json`（無いときに 1 回だけ）、アプリのプロセス ID を入れた小さなロックファイル（`/run/user/<uid>`。メモリ上だけのフォルダ。無い環境では `/tmp`）、そして新しい版を確認・インストールしたときだけ、更新の仕組みが使うキャッシュ `~/.cache/frame-perf-overlay/`（前回確認した答え、インストールの進み具合・ログ、動いている間のロックのフォルダ、ダウンロードした tar.gz と展開した中身を置く作業フォルダ `update/`。作業フォルダはインストールが終わると空にします。更新の仕組みのスクリプトのコピーはそこに残ります。[更新](#更新)を参照）
- 手に付けているときは、パネルを置いて薄くするために、そのコントローラーと本体の位置・向きを SteamVR から読みます。メモリの中で使うだけで、保存・ログ・送信はしません
- ログはヘッドセットの中の systemd のジャーナルに残るだけです

## 開発

ビルドはヘッドセット上で行います（SteamOS の cairo・FreeType・libnl・Vulkan ローダーと、SteamVR の `libopenvr_api.so` にリンクするため）。必要な道具とライブラリは SteamOS に入っています: cmake、ninja、g++、pkg-config、cairo・freetype2・vulkan・libnl-genl-3.0 の開発用ファイル。`openvr.h`（OpenVR SDK 2.15.6）は `third_party/openvr/` に同梱しています。

```sh
cmake -G Ninja -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure  # テスト（手首の位置と向き・フェード・時計・設定ファイルとその移行・設定パネルのボタン・画素の変換・センサー・ウィジェットとレイアウトの編集・読み取りのスケジュール）
./install.sh               # build/frame-perf-overlay を入れる
scripts/package.sh         # リリース用にビルドして dist/frame-perf-overlay-<バージョン>.tar.gz と dist/SHA256SUMS を作る
```

確認に便利なオプション（最後のもの以外は SteamVR なしで動きます）:

```sh
./build/frame-perf-overlay --print --count 5        # 読み取った値を 1 秒おきに 5 回表示
./build/frame-perf-overlay --dump-png panel.png --seconds 30 --fake-frames --language ja
./build/frame-perf-overlay --dump-png grid.png --layout my-layout.json --fake-frames  # 別のレイアウト（レイアウトのオブジェクトか、設定ファイルまるごと）
./build/frame-perf-overlay --dump-settings-png layout.png --preview-page layout --preview-select 0,2 --language ja
./build/frame-perf-overlay --dump-metrics --widgets 1,4 --count 3  # すべての値と、スケジューラーが読んだもの（オーバーレイなしで）
./build/frame-perf-overlay --debug-dump             # 動いているアプリの読み取り元・読んだ回数・値
./build/frame-perf-overlay --dump-settings-png settings.png --language ja
./build/frame-perf-overlay --dump-settings-png wrist.png --config wrist.json --language ja  # wrist.json: {"attachment": "left_wrist"}
./build/frame-perf-overlay --dump-settings-png update.png --preview-update available --language ja
./build/frame-perf-overlay --contrast-report        # 使っている色の組み合わせごとの WCAG のコントラスト比
./build/frame-perf-overlay --verbose                # オーバーレイとして動かし、数秒ごとに値をログに出す
```

すべてのオプションは `--help` で見られます（`--preview-update` の状態の一覧も）。

コードは `core/`（プラットフォームに依存しない部分: 値の登録表、値の置き場、必要なものだけを読むスケジューラー、レイアウトとその編集）、`core/render/`（cairo: ウィジェットと、それを並べて描く部分）、`headset/`（OpenVR、センサー、ダッシュボードのタブ）に分かれています。値はすべて登録表を通ります。値ごとに持ち主のウィジェットと読み取り元が 1 つずつ決まっていて、読み取り元は、パネルのウィジェットがそれを必要としていて、誰かが見ているときだけ読みます。バージョンは `CMakeLists.txt` の `project(... VERSION ...)` で決まり、`--version` で表示されます。

リリースのビルドは、サイズ優先の最適化・使わない部分の削除・LTO（コンパイラが対応していれば）を使います。`-DFRAME_PERF_OPTIMIZE_SIZE=OFF` にすると、ふつうの速さ優先の最適化（LTO つき）になります。例外や浮動小数点の扱い、デバッグビルドは変わりません。テストには、画素の変換と位置の計算を厳密に確かめるものと、作り物のファイルで CPU・GPU のセンサーを確かめるものがあります。`./build/ui-helpers-test --benchmark` で、変換の CPU 時間を前のやり方と比べられます。

`vendor/frame-updater/` は、非公開の共通の更新の仕組み（スクリプト、このアプリがビルドする C++ の部品、更新の帯の文言）のコピーです。ここでは編集しないでください。`scripts/package.sh` が元とずれていないか確かめます。

## リリース（メンテナー向け）

ヘッドセット上で `scripts/package.sh` を実行すると、Release でビルドし（先に `vendor/frame-updater/` が手で書き換えられていないか確かめます）、tar.gz を作って隣に `dist/SHA256SUMS` を書き出します。公開に使う正確なコマンドを最後に表示します:

```sh
gh release create v<バージョン> dist/frame-perf-overlay-<バージョン>.tar.gz dist/SHA256SUMS --title v<バージョン> --generate-notes
```

パネルの中の［更新］ボタンが使えるようにするには `SHA256SUMS` を必ず添付してください。無いと「ここからは入れられません」とリリースページを示すだけになります。
